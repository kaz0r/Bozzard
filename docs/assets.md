# Asset imports

Run `cargo run -p bozzard-player -- --scene examples/demo/scenes/asset-lab.json` for the file-backed reference scene. It uses imported 2D quads, a four-color PNG, and 3D octahedra. The embedded default remains usable without external files.

## Catalog and references

Scene version 1 accepts an optional `assets` object:

```json
"assets": {
  "portrait": { "kind": "image", "path": "assets/portrait.png" },
  "statue": { "kind": "mesh", "path": "assets/statue.obj" }
}
```

A drawable selects `"texture": {"asset":"portrait"}` or `"mesh": {"asset":"statue"}`. Existing `white`/`checker` textures and `quad`/`cube` meshes still work. An ID is an authored string, independent of the filename. Keep it unchanged when relocating a source file. Missing references and image/mesh kind mismatches fail scene validation. `Scene::asset_users()` reports which objects use each ID; OBJ materials do not add hidden file dependencies.

Paths use forward slashes and are relative to the scene file, never the process's working directory. Parent segments are allowed so a snapshot saved elsewhere can refer back to its source assets. The player/server rebase references when saving into another folder, preserving IDs; they do not copy files. Saving requires the referenced files to exist and rejects cross-drive relative paths. Move a scene together with its referenced files when sharing it. The development bundler includes the supplied asset lab and source files and verifies a relocated snapshot after extraction.

## Supported formats

- PNG/JPEG: up to 4096×4096, decoded to RGBA8 and sampled as sRGB using nearest/repeat filtering. The current material pass is opaque; images containing non-opaque alpha are rejected. ICC color management, HDR, mipmaps, filtering options, and compressed GPU formats are not part of this slice.
- OBJ: static triangle meshes, with convex polygons triangulated by `tobj`. Export triangles for predictable results with concave geometry. Groups are combined into one mesh and use the drawable's single material. Positions are used as authored in right-handed Y-up coordinates. Missing normals are generated by accumulating triangle normals at shared vertices; supply split normals for hard edges. Missing UVs become zero. OBJ's bottom-left UV origin is converted to the renderer's top-left origin. Point/line primitives are ignored; empty, degenerate, non-finite, or invalid indexed geometry is rejected. MTL files are rejected explicitly; assign textures/tint in the scene. No skeletal animation, glTF, or PBR import yet.

Sources are limited to 32 MiB each. Imported geometry is limited to one million vertices and three million indices. These are initial safeguards, not a streaming or aggregate memory budget.

## Reload behavior

The CPU store exposes private store-scoped handles, `Pending`/`Ready`/`Failed` states, last-good data, and a revision that advances only after a successful import. Loading is synchronous. Startup fails visibly if any catalog asset cannot load; there are no silent placeholder substitutions.

The native player checks source contents every 500 ms, including while paused. A changed file triggers import and GPU replacement. Corrupt/incomplete/deleted files produce a terminal diagnostic and leave the previous asset visible. Repairing the file reloads it without restarting. Content comparison detects equal-length edits and avoids relying on coarse file timestamps. Changing the catalog itself requires R to reload the scene; a failed scene reload preserves the old world and renderer.

Polling retains source bytes and imports on the main thread, so large projects can stall. Async jobs, cancellation, file watchers, unloading, transitive material dependencies, and streaming remain extensions of this baseline. The finite headless server validates the catalog but does not decode or upload rendering assets.

## Acceptance checks

CPU tests exercise stale/foreign store handles, failed reload preservation, deletion/recovery, OBJ normals and UV conversion, and saves across directories. GPU checks import files, verify four independent texture colors including sRGB gray, corrupt and repair a texture, and replace a mesh so the center pixel becomes background. Packaged checks load the included asset lab from an empty working directory; Linux CI also presents its two views under Xvfb.

Importers: [`image` ImageReader](https://docs.rs/image/0.25.10/image/struct.ImageReader.html) and [`tobj` LoadOptions](https://docs.rs/tobj/4.0.5/tobj/struct.LoadOptions.html), with exact resolved versions in `Cargo.lock`. Bozzard owns asset identity, loading state, scene dependencies, reload policy, and GPU caches.

The tiny generated palette PNGs and OBJ geometry under `examples/demo/scenes/assets/` are original Bozzard test fixtures, dedicated to the public domain under CC0. They intentionally emphasize testable colors and shapes rather than production artwork.
