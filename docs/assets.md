# Asset imports

Run `cargo run -p bozzard-player -- --scene examples/demo/scenes/asset-lab.json` for the file-backed image/OBJ reference scene. The Model Workshop example is `examples/demo/scenes/model-lab.json`; it includes the original CC0 `courier.gltf`/`.glb`, external `.bin` and texture resources, and an OBJ reference.

## Catalog and references

Scene version 1 accepts an optional `assets` object:

```json
"assets": {
  "portrait": { "kind": "image", "path": "assets/portrait.png" },
  "statue": { "kind": "mesh", "path": "assets/statue.obj" },
  "courier": { "kind": "mesh", "path": "assets/courier.gltf" }
}
```

A drawable selects `"texture": {"asset":"portrait"}` or `"mesh": {"asset":"statue"}`. Existing `white`/`checker` textures and `quad`/`cube` meshes still work. An ID is an authored string, independent of the filename. Keep it unchanged when relocating a source file. Missing references and image/mesh kind mismatches fail scene validation. `Scene::asset_users()` reports which objects use each ID.

Paths use forward slashes and are relative to the scene file, never the process's working directory. Parent segments are allowed so a snapshot saved elsewhere can refer back to its source assets. The player/server rebase references when saving into another folder, preserving IDs; they do not copy files. Saving requires the referenced files to exist and rejects cross-drive relative paths. Move a scene together with its referenced files when sharing it. The editor copies imported files into an `assets/` folder next to the scene. glTF/GLB imports are packaged under `assets/<id>/` as `model.gltf` plus generated flat external `buffer-*.bin` and `image-*` files, preserving glTF metadata and buffer-view images without expanding the model into large base64 JSON. Material-bearing OBJ imports continue to use the existing packed single `.gltf` file with embedded resources.

The glTF/GLB package directory is owned by the import until the import is accepted. Cancellation, a stale result, or failed delivery removes that directory; accepted imports keep it, and remove/undo operations keep the source files available for reuse. As a size reference, the current imported Sponza package has a 97,727-byte `model.gltf` document and a package folder of about 50 MiB, because the binary resources remain external.

## Supported formats

- PNG/JPEG: up to 4096×4096, decoded to RGBA8 and sampled as sRGB using nearest/repeat filtering. Non-opaque alpha is supported by the renderer's transparent surface path. Mipmaps, custom filtering, ICC color management, HDR, and compressed GPU formats are not part of this slice.
- OBJ: static triangle meshes, with convex polygons triangulated by `tobj`. Export triangles for predictable results with concave geometry. Groups are combined into one mesh. Positions are used as authored in right-handed Y-up coordinates. Missing normals are generated by accumulating triangle normals at shared vertices; supply split normals for hard edges. Missing UVs become zero. OBJ's bottom-left UV origin is converted to the renderer's top-left origin. Point/line primitives are ignored; empty, degenerate, non-finite, or invalid indexed geometry is rejected. MTL diffuse textures are supported when resources resolve beside the OBJ; other material properties remain outside this slice.
- glTF 2.0/GLB: static meshes from the default scene, including node hierarchy transforms baked into vertices, multiple triangle primitives/surfaces, base-color factors and base-color textures. Embedded data URIs, GLB BIN/image chunks, and external resources below the model directory are supported. Material alpha modes Opaque, Mask, and Blend are preserved; Mask uses the source cutoff. CPU import preserves supported metallic/roughness, normal, occlusion, emissive, double-sided, tangent, UV, and sampler data for the renderer. Skins, animations, morph targets, Draco/meshopt geometry compression, BasisU/WebP/DDS textures, and non-triangle primitive modes are rejected; the UV set requested by the base-color texture is used. Required glTF extensions are rejected. Vertex colors are not rendered and produce a warning.

Imported model base-color, metallic/roughness, normal, occlusion, and emissive textures receive GPU-generated mipmaps and use their authored wrap, minification, magnification, and mipmap sampler settings, with independent UV sets. sRGB base-color and emissive textures are kept separate from linear normal, metallic/roughness, and occlusion textures while sharing decoded source images where possible. Standalone imported images and procedural textures retain nearest filtering with repeat addressing.

The CPU import checkpoint (`SurfaceShading`) preserves metallic and roughness factors and texture, normal texture and scale, tangents, occlusion texture and strength, emissive texture and factor, double-sided state, and each map's sampler and UV-set settings. Missing tangents are generated with accumulated UV-derivative triangles; this is a conventional generator, not MikkTSpace. Finite source tangents parallel to their normals are repaired from normal-map UVs and produce an importer warning.

Sources are limited to 32 MiB each. Imported geometry is limited to one million vertices and three million indices. Models are also limited to 4096 surfaces and 256 hierarchy levels. External dependencies are bounded to 256 files and 128 MiB combined; decoded buffers remain limited to 128 MiB. OBJ decoded images remain limited to 128 MiB; glTF unique decoded image data has a 512 MiB budget to accommodate complete PBR map sets. For scale, Sponza's shared unique images decode to about 272 MiB (roughly 15.34 seconds in a debug import).

glTF surfaces sharing a source image now reuse its decoded pixels and GPU texture within the model. Opaque alpha handling uses a separate variant when necessary. The image budget counts unique decoded variants. `cargo run -p bozzard-assets --example inspect -- MODEL.gltf` reports CPU import/check times, geometry bounds and shared decoded-image memory; renderer model upload statistics expose surface count, unique texture count, texture bytes, CPU submission time, preparation time, upload-slice count, maximum slice bytes, and maximum slice CPU time. The slice CPU-time value is observational and is not a guarantee (these statistics do not report GPU elapsed time).

The editor can pick the nearest triangle of an imported model in the viewport and inspect its virtual **Imported surfaces** list. Searchable rows show source node/mesh/primitive and material names where available, with read-only factors, map dimensions, and sampler details. **F** or **Frame surface** frames the selected surface; **Shift+F** frames the whole layer. Surface selection is transient, but its transform and material edits are saved per model instance. Gizmos and Properties edit that surface; image assignment targets only its texture. Duplicate/delete and component editing still require selecting the owner. Picking pauses while CPU model data differs from the GPU's last-good resident data; outlines and framing wait for matching graphics. Selection is tied to the immutable CPU asset identity, so failed reloads retain it and successful new data or Play clears it. glTF source hierarchy is shown as labels; each imported primitive can be transformed independently without expanding it into a separate scene object. OBJ material parts retain their names where present; an unpartitioned OBJ remains a whole object with no synthetic inspectable surface list.

### Editing a submesh

1. Click its geometry or hierarchy row. **W / E / R** gizmos and **Properties → Transform** move, rotate, and scale just that surface. Offset is in model space; rotation/scale pivot around its source bounds center. Mirrored scales are supported. **Reset transform** restores its imported pose.
2. Enable **Override texture / effect** to choose an imported image, checker, or built-in effect. Import PNG/JPEG through **Content Browser**, then choose it in Properties or use the browser's **Assign to selected** action. **White / no map** explicitly removes the base-color map; unchecking the override inherits the owner/source texture. **UV repeat**, tint, and PBR metallic/roughness controls apply only to this surface. **Reset override** resets its material without resetting its transform. Existing normal, metallic/roughness, occlusion and emissive maps remain inherited.
3. **Alt-click** or **Select whole model** returns to owner transforms and components. Surface edits follow the owner. Colliders, gameplay components, duplicate/delete and renaming remain owner-level; this is not vertex editing or automatic splitting of disconnected pieces within a primitive.

Edits reuse the backward-compatible `material_overrides` entries, keyed by surface index and source signature, adding optional/defaulted `transform`, `texture`, and `uv_scale` fields. Undo/redo, save/reopen, duplication and Play preserve the edits independently per instance. Render/shadow transforms, bounds, ray picking and GI transport follow the edited surface; GI edits invalidate the old bake. Texture references participate in dependency validation, usage counts and removal guards. If geometry or source names change, a signature mismatch leaves the saved edit inactive with an inspector warning. Shared CPU/GPU source geometry is never rewritten or reuploaded for a surface edit. OBJ diffuse parts support transforms, texture and tint, but not PBR factors.

The renderer applies glTF metallic/roughness GGX shading, normal mapping, indirect-only ambient occlusion, sRGB emissive, double-sided materials, and reflected transforms. Scenes may optionally author one global sun and diffuse ambient term: `sun_direction` points toward the sun and is normalized for rendering; sun color/intensity default to linear white/3, and ambient color/intensity default to white/0.03. Scene lighting validates finite nonzero directions, RGB values in 0..1, and intensities in 0..100000. Objects may also carry an optional point or spot `Light` component, with the 32-component cap and range/angle rules documented in [point and spot lights](lighting.md). Both PBR and legacy lit surfaces consume these settings; legacy lighting uses Lambert sun/π plus ambient, while unlit surfaces remain unlit. The editor's Scene lighting inspector is always available with azimuth/elevation, colors, intensities, and reset controls, and follows normal history and Play-mode rules.

Scenes may optionally author `display` settings: `exposure_ev` defaults to 0 and is finite in -16..16 stops, where +1 doubles radiance, and `tone_mapping` defaults to enabled. Bloom is disabled by default; its intensity defaults to 0.15 (0..10), threshold to 1 (0..60000 scene-linear radiance before exposure), and scatter to 0.7 (0..1). All 3D shading and alpha blending accumulate in bounded `Rgba16Float` scene color (scene radiance is capped at 60000); enabled bloom extracts bright HDR color and composites it before exposure and per-channel Reinhard tone mapping `x/(1+x)`. Disabling tone mapping bypasses only the curve and still applies exposure. Final output uses the hardware sRGB target when available or shader sRGB encoding otherwise. 2D extraction bypasses exposure, bloom, and tone mapping but still uses normal display encoding. Auto-exposure is not implemented. The editor's Scene lighting inspector exposes Display (3D) exposure, tone-mapping, bloom, and reset controls with the same Undo and Play-mode rules. The `draw_linear` diagnostic API bypasses these transforms, including bloom, for numeric shader fixtures and requires a non-sRGB target; production drawing uses the scene settings. Actual-scene smoke PPM captures now contain display-encoded output; captures from before this checkpoint contained linear bytes.

Sun shadows are enabled by default and use one `Depth32Float` directional map covering the bounds of all lit world geometry, independent of the camera. `shadow_resolution` is a power of two from 256 to 4096 (default 2048; the editor offers 512, 1024, 2048, and 4096), with `shadow_bias` defaulting to 0.005 and `shadow_normal_bias` to 0.01 world units; both bias values are constrained to 0..1. The shadow projection center is snapped to shadow texels. A 3×3 PCF comparison applies depth, slope, and normal bias. Caster alpha uses its base-color cutoff, authored sampler/UV/tint, PBR double-sided state, and reflected winding; alpha-blended surfaces receive shadows but do not cast them. Ambient, emissive, and unlit contributions are unaffected. The Scene lighting inspector exposes the shadow checkbox, resolution, and biases. The map spreads its finite resolution over the whole scene, so shadow detail decreases as scene bounds grow. Point/spot lights have no local shadow maps; cascades, local reflection probes, and auto-exposure remain future work. See [bloom and display](lighting.md#bloom) for the post-process display effect.

Transparent surfaces are sorted by their centers and blended without writing depth; intersecting transparent surfaces can still show ordering artifacts. OBJ imports preserve diffuse color, opacity, and diffuse images only.

The renderer performs a conservative per-surface homogeneous AABB clip test in the main color pass. Offscreen shadow casters remain retained so shadow bounds stay stable. Compatible consecutive draws reuse cached pipelines and shared shadow/environment bindings without changing draw or alpha order. `FrameStats` reports scene items, visible/culled surfaces, color triangles, shadow draws/triangles, pipeline binds, and CPU total/prepare/encode/submit milliseconds; these are CPU-side metrics, not GPU time or FPS. The editor shows a compact metrics overlay in the viewport. Diagnostic setters can enable or disable culling and the state cache. `bozzard-player --smoke --scene FILE --benchmark-frames N` (1–1000) compares reference, culling, and full-cache configurations after warmups with interleaved timing and synchronized GPU waits; it logs CPU and synchronized CPU+GPU+wait medians, not FPS. GPU timestamps, multidraw, instancing, and occlusion culling are not implemented.

Scenes may optionally author one procedural distant environment, enabled by default, with linear-RGB zenith `[0.15, 0.32, 0.65]`, horizon `[0.65, 0.70, 0.80]`, ground `[0.12, 0.10, 0.08]`, intensity `0.35`, and a background flag. Colors are constrained to 0..1 and intensity to 0..1000. Distant sky bands blend by `sqrt(abs(direction.y))`, and the background is inverse-camera correct. On first enabled use, the GPU precomputes a 32px diffuse cosine-convolved cubemap, 128px GGX specular cubemap with 8 mip levels, a 64px split-sum BRDF LUT, using 128 deterministic Hammersley samples. Later color/intensity edits update uniforms only because convolution is linear. PBR surfaces use diffuse and roughness-dependent specular IBL, legacy lit surfaces use diffuse environment light, AO affects indirect light, and unlit surfaces remain unchanged. 2D extraction disables the environment. The Scene lighting controls expose environment colors, intensity, background, and reset in a panel capped at 360px. This is a procedural environment only: HDR panorama import, local reflection probes, scene occlusion of the environment, and atmospheric simulation are not implemented. Baked diffuse GI is a separate bounded static probe volume; see [baked global illumination](lighting.md#baked-global-illumination) for its source fingerprint and transport limits. The split-sum approach follows the design described in [Filament's material documentation](https://google.github.io/filament/main/filament.html); the implementation is Bozzard's own.

## Reload behavior

The CPU store exposes private store-scoped handles, `Pending`/`Ready`/`Failed` states, last-good data, and a revision that advances only after a successful import. Player startup and command-line scene loading remain synchronous: the scene and its catalog are decoded and validated before the player starts, and startup fails visibly if any catalog asset cannot load. There are no silent placeholder substitutions.

Editor and player GPU residency use a shared immutable CPU `Arc` snapshot and one preparation worker per residency. Resource validation and allocation preparation happen there; a cancelled or stale preparation remains tracked until terminal, so overlapping workers cannot start. The final atomic install occurs only after all buffer and texture writes and mip passes have been submitted. A failed replacement preserves the last-good GPU asset, and stale or cancelled jobs are never published.

Uploads advance by at most 4 MiB of payload plus generated-mip output per frame, with a soft 4 ms CPU slice checked between operations; this is a scheduling budget, not a hard wall or GPU-time guarantee. Buffer encoding and level-0 texture copy/alpha-scan operations are each capped at 256 KiB, while textures are written in rows, vertex/index/PBR attribute buffers are chunked, and mip passes are scissored into rows. Small material-uniform initialization happens during background preparation. Editor progress reports **Preparing** and **Uploading** with **Cancel this upload**; initial GPU resources block the viewport and show a status panel while the surrounding editor panels remain responsive. Player startup and CLI loading drain the same queue synchronously, while player hot reload continues running.

Catalog edits and Undo/redo re-upload only data whose identity changed; removed entries retire individually. A failed replacement is not retried every frame; explicit **Reload** permits a retry. Uploads still execute on the render thread, and the frame upload queue is not a GPU-time guarantee.

The native editor keeps its initial file open responsive after reading and validating the scene document: catalog loading runs in a bounded background job. Opening a scene and importing a dropped asset show progress stages and publish the result only when the main thread accepts it. Import progress can include preparing the import, reading and packing model resources, decoding, copying into the project, and validating project assets. Cancellation prevents an open result from being published; stale import or refresh results are discarded. A prepared import that is cancelled or fails delivery removes the newly created project file. The editor's periodic catalog refresh also runs in the background. The embedded default scene path still constructs its initial asset store synchronously.

Editor saves also prepare and validate the rebased scene and catalog in a background job. The final atomic JSON write occurs on the UI thread only after preparation succeeds and the editor path and document revision are unchanged. Cancelling a save prevents publication. “Save and continue” waits for that same save job before completing the pending open, new-scene, or close action.

Undo and redo retain the decoded asset store with history entries, so moving through editor history reuses cached data instead of rereading source files. Explicit open, import, and save jobs temporarily disable authoring controls. Hot reload keeps authoring available while its background job runs. Cancelling a job prevents publication, but the current codec/import call may finish before cancellation is observed; its result is then discarded.

The player and editor check for source changes about every 500 ms. Their hot-reload jobs report checking and decoding stages, then publish CPU data before the render thread replaces the corresponding GPU resource. A reload failure keeps the last-good asset visible. Cancelling editor reload pauses automatic reload until **Reload** is clicked; the player has no reload-cancel control. Dropping a job also requests cancellation.

The native player checks source contents every 500 ms, including while paused. A changed file or tracked glTF/OBJ dependency triggers import and GPU replacement. Corrupt/incomplete/deleted files produce a terminal diagnostic and leave the previous asset visible. Repairing the file reloads it without restarting. Content comparison detects equal-length edits and avoids relying on coarse file timestamps. Changing the catalog itself requires R to reload the scene; a failed scene reload preserves the old world and renderer.

The finite headless server validates the catalog but does not decode or upload rendering assets. File watching, unloading, and streaming remain extensions of this baseline.

## Acceptance checks

CPU and GPU acceptance checks cover image alpha, OBJ materials, glTF/GLB transforms, primitives, materials, external/data-URI resources, rejection of unsupported static features, dependency reload, portable packing, and editor browser operations. The Model Workshop fixture exercises the supported model and texture combinations.

Importers: [`image` ImageReader](https://docs.rs/image/0.25.10/image/struct.ImageReader.html), [`tobj` LoadOptions](https://docs.rs/tobj/4.0.5/tobj/struct.LoadOptions.html), and [`gltf`](https://docs.rs/gltf/1.4.1/gltf/), with exact resolved versions in `Cargo.lock`. Bozzard owns asset identity, loading state, scene dependencies, reload policy, and GPU caches.

## Editor asset browser

The native editor's Assets panel searches and filters the catalog by All, Images, or Models. Image thumbnails are bounded to 192 pixels per edge; models show a bounded geometry sample. Selecting an entry shows its path, load state or error, image dimensions or model vertex/triangle counts, importer warnings, and object usage count. The panel can import, reload, add an asset to the scene, assign it to the selected drawable, or remove an unused catalog entry. Removing an entry supports undo and never deletes its source file. Imported model additions use a white tint; imported images can be added as aspect-ratio-preserving quads.

The generated courier glTF/GLB models, buffers, PNG textures, and OBJ geometry under `examples/demo/scenes/assets/` are original Bozzard test fixtures, dedicated to the public domain under CC0. They intentionally emphasize testable colors and shapes rather than production artwork.

### Measured Sponza checkpoint

On an Apple M2 Pro, a debug Metal run at 800×500 with 4096px sun shadows and 30 measured frames per configuration produced identical pixels in all three paths. Reference rendering issued 103 color draws / 262267 triangles / 103 color pipeline binds; culling reduced this to 89 draws / 257752 triangles, and state caching reduced color pipeline binds to 1. All 103 shadow draws / 262267 shadow triangles remained. Median renderer CPU time was 18.189 ms reference, 17.200 ms with culling, and 17.045 ms with culling plus cached state. Synchronized CPU+GPU+wait medians were 23.977, 22.810, and 22.924 ms respectively; the small difference between the latter two is not evidence of a GPU speedup. These are one-machine debug measurements, not production FPS or cross-platform performance claims.
