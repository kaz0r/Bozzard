# Batch rendering implementation coverage

This maps all 43 items in the [original main review](batch-rendering-roadmap.md), pinned to main `2b4351083dfb6dbb25221c75e8e3c1dabc72c835`, to code, reproducible tests and conservative limits. The [proof report](batch-rendering-optimizations.md) records executed validation, before/after release measurements and raw evidence. Work-count reductions below belong to their named fixtures; they are not additive or predictions of overall FPS.

The most recent completed native affected-target rerun at runtime `3fff7d9` passed 127 tests with 0 failures and 5 ignored tests on Apple M2 Pro / Metal: 112 library tests and 15 instancing integration tests. The [validation manifest](measurements/batch-rendering-optimizations/validation/validation.json) at `7712c97a` records 158 renderer passes and 354 unique passing Rust tests across the selected packages, with 7 ignored. Those mixed-source totals include 13 preparation/submission/surface-variant passes retained at `356b3ab` and 18 other earlier renderer passes; every retained scope preserves its recorded source, command and log hash. Current workspace Clippy, formatting and the optimized release build passed; Steam/factory Clippy retain their successful `356b3ab` scope. The supporting 25-test CPU reuse/spatial run, including the committed real Factory envelope/rank regression, repeats names passed in the final native library and adds no unique passes. An earlier aggregate stopped at the former camera-churn fixture's unconditional reuse assertion; test-only repair `dd14ec7` preserves exact pixel and reuse checks while making each compatibility key fit one portable batch, and the current complete instancing target passed. These executed fixture results establish the specific contracts below; final three-run release workload timing and parity are recorded in the proof report.

The final comparison at `3fff7d9` completed three alternating process pairs for both release profiles on Apple M2 Pro / Metal. Extraction-plus-rendering CPU medians were 11.0% lower for active, 17.2% lower for frozen and 9.5% lower for camera-only factory workloads. Renderer-only active CPU was effectively flat, frozen median was 2.6% higher with overlapping ranges, and camera-only was 11.5% lower. All twelve processes passed 144 exact internal RGBA paired assertions and unchanged scene/checkpoint checks. Of 144 cross-main RGB comparisons, 96 were byte-exact; the remaining 48 differed by one 8-bit step in one channel at one pixel each. Full medians/ranges, command/executable/capture hashes, limitations and raw frame reports are in the [proof report](batch-rendering-optimizations.md) and [raw comparison](measurements/batch-rendering-optimizations/summary.json). ## Deliberate limits

The implementation keeps safe fallback paths for invalid/duplicate identities, uncertain geometry or coverage, portable devices and unsupported native multi draw. Metal executes the portable/native object arena and direct submission fallback; it does not establish a native multi-draw speedup.

The roadmap also identified conditional experiments: depth/resource timing weights, merging unchanged upload gaps, drawable-only transform filtering, atlases/arrays, GPU-cost-calibrated occlusion admission and primitive cache/overdraw reordering. These are not asserted as completed features. The chosen implementation uses legal fuller scheduling, contiguous dirty writes, conservative component freshness and lossless vertex welding/fetch ordering while preserving authored primitive order.

GI freshness deliberately invalidates on any owned component mutation, so unrelated dynamic writes can still recapture it. Asset publication changes can still scan the catalog once, and required-name membership walks remain linear. Shared skinning uses real physical output handles but keeps private spare buffers allocated.

Resource limits describe retained logical payload. They do not include driver overhead, resources retained by submitted GPU commands, or shared immutable backing retained elsewhere. Budget rejection uses the original full-render path, with exact-output tests.
